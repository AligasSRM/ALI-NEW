## نظام الترقيم الهندسي الثابت A/B/C

هذا هو نظام التتبع المعتمد داخل **ALI-NEW**، ويكمل تسلسل المراحل A0–A12 ولا يستبدله:

- **A**: مرحلة هندسية قائمة، من A0 إلى A12؛ لا يُغيّر ترتيبها أو معناها بلا قرار موثّق.
- **B**: قسم فرعي داخل مرحلة A، يبدأ ترقيمه من B0 ثم B1 وما يلزم.
- **C**: مدخل ملف فعلي داخل قسم B، يبدأ من C0 ثم C1 وما يلزم.
- **المعرّف الكامل** مثل `A0/B1/C2` يحدد المرحلة والقسم والملف معًا؛ ويمكن تكرار B0 أو C0 تحت آباء مختلفين، لكن لا يُكرر المعرّف الكامل ولا تُمنح نسخة ثانية من الملف هوية C أساسية.
- يُربط كل C بمسار الملف الحقيقي وحالته وغرضه ودليله. الأقسام المخططة تُوسم بوضوح ولا تُعرض كملفات موجودة.

**ثوابت النظام:** لا تنشئ مجلدات أو ملفات لتناسب الترقيم، ولا تنقل أو تعِد تسمية الملفات بسببه، ولا تختلق مسارات أو عناصر لملء فجوات. قبل تحديث الفهرس، افحص شجرة المستودع والفرع والـ commit المستهدف؛ وبعد إضافة ملف، حدّث السجل وواجهة شجرة علي وتحقق من التطابق. وجود الملف أو المعرّف لا يعني أن المرحلة مقبولة أو GREEN.

المرجع التفصيلي الحاكم لهذا النظام هو [المرجع الهندسي وتسلسل المراحل](PROJECT-BUILD-TREE.md)؛ هذا القسم ملخص ثابت في README وليس فهرسًا بديلًا.

## خارطة التنفيذ التفصيلية — من A0 إلى A12

**ترتيب العمل إلزامي:** A0 ← A1 ← A2 ← A3 ← A4 ← A5 ← A6 ← A7 ← A8 ← A9 ← A10 ← A11 ← A12. لا نبدأ مرحلة تالية قبل اجتياز بوابة الحالية وتسجيل الأدلة، إلا بعمل اعتماد تقني ضيق وموثّق لا يُغلق المرحلة اللاحقة. التفصيل أدناه يشرح الهدف والخطوات والمخرجات وبوابة القبول؛ المرجع الهندسي يظل المصدر الحاكم للتسلسل والقرارات.

### A0 — الجرد والهوية ولوحة التحكم
- **الهدف:** مرجع واضح للمشروع، وشجرة المراحل، والحالة الحالية، وروابط الأدلة.
- **الخطوات:** جرد الملفات والمسارات؛ تدقيق شجرة A/B/C؛ مراجعة الهوية والتصميم والتنقل؛ فحص الهاتف والكمبيوتر ولوحة المفاتيح وقارئ الشاشة؛ مراجعة الروابط وأخطاء المتصفح ورؤوس الأمان المنشورة.
- **المخرجات:** لوحة تحكم موثقة، سجل جرد مطابق للـ Git tree، تقرير اختبارات، وقائمة بوابات مفتوحة.
- **بوابة القبول:** مراجعة بصرية نهائية، تحقق يدوي للوصولية، وحسم ملاحظات رؤوس الأمان مع أدلة. **الحالة الحالية YELLOW؛ لا تُعد مغلقة.**

### A1 — تعريف المنتج والمتطلبات
- **الهدف:** الاتفاق على المنتج الذي سنبنيه ولمَن، وما الذي يدخل النطاق وما الذي يستبعد منه.
- **الخطوات:** تحديد المشكلة والقيمة؛ تحديد المستخدمين واحتياجاتهم؛ تعريف المصطلحات والسيناريوهات الأساسية؛ كتابة الوظائف والقيود غير الوظيفية؛ ترتيب الأولويات؛ تسجيل الأسئلة والقرارات المفتوحة؛ تحديد معايير قبول قابلة للاختبار لكل مطلب.
- **المخرجات:** تعريف منتج معتمد، قائمة متطلبات ذات معرّفات، نطاق واستثناءات، مخاطر وافتراضات، ومعايير قبول واضحة.
- **بوابة القبول:** لا تناقضات جوهرية ولا متطلبات غامضة بلا مالك أو قرار؛ اعتماد صريح لتعريف المنتج. الوثيقة الموجودة حاليًا **مسودة PLANNED غير معتمدة**.

### A2 — تجربة المستخدم والتصميم
- **الهدف:** تحويل المتطلبات المعتمدة إلى تجربة بسيطة وأنيقة ومتسقة على الهاتف والكمبيوتر.
- **الخطوات:** رسم رحلات المستخدم؛ حصر الشاشات وحالاتها؛ تحديد الهيكل والتنقل؛ وضع نظام التصميم والمكونات؛ تصميم حالات التحميل والفراغ والخطأ والنجاح؛ دعم العربية RTL واللغات المطلوبة؛ تحديد قواعد التجاوب والوصولية؛ مراجعة النماذج الأولية مع المتطلبات.
- **المخرجات:** خريطة شاشات ورحلات، نماذج وتصميم معتمد، رموز تصميم ومكونات مشتركة، وقائمة حالات الواجهة.
- **بوابة القبول:** كل مطلب مربوط برحلة أو شاشة واختبار؛ اتساق بصري وسهولة استخدام موثقان، مع فحص RTL والتجاوب والوصولية. وجود تصاميم سابقة لا يعني قبول المرحلة كاملة.

### A3 — المعمارية وحدود النظام
- **الهدف:** تحديد كيف تعمل أجزاء المنصة وكيف تتبادل البيانات بأمان، قبل بناء التطبيق الأساسي.
- **الخطوات:** رسم مكونات النظام وتدفق البيانات؛ تعريف نموذج المجال والكيانات والعلاقات؛ تحديد حدود الثقة والصلاحيات؛ وصف عقود API والأخطاء؛ بناء نموذج تهديد؛ تحديد حدود التكاملات ومحوّلات المزوّدين؛ توثيق خيارات التخزين والمعالجة والقيود؛ تحديد التصدير والترحيل وخطة الخروج والاسترجاع.
- **المخرجات:** مخطط معمارية، نموذج بيانات أولي، عقود واجهات، سجل قرارات ومخاطر، وخطط ترحيل وتراجع.
- **بوابة القبول:** مراجعة المعمارية والأمن والخصوصية والتكلفة والاعتمادية؛ تبرير القرارات المهمة والبدائل، وعدم اختيار اعتماد مدفوع دون الموافقة المطلوبة.

### A4 — المستودع وسير التطوير
- **الهدف:** تأسيس طريقة تطوير قابلة للتكرار والمراجعة دون إرباك الشجرة أو كسر المشروع.
- **الخطوات:** تثبيت هيكل الملفات عند الحاجة؛ قواعد التسمية والترقيم؛ إعداد الفحص والتنسيق والاختبارات؛ تحديد الفروع وطلبات الدمج والمراجعة؛ ضبط CI؛ فحص الأسرار والاعتماديات؛ توثيق أوامر التطوير والتشغيل؛ التأكد من إمكانية إعادة الاختبارات.
- **المخرجات:** قواعد مساهمة، أوامر واضحة، فحوص آلية، سير PR/CI، وسجل تبعيات.
- **بوابة القبول:** نجاح الفحوص المطلوبة على commit محدد، وإثبات أن التغييرات محدودة وقابلة للمراجعة والتراجع. لا تُنشأ مجلدات أو أدوات بلا حاجة مثبتة.

### A5 — الحسابات والهوية والتحقق
- **الهدف:** إدارة هوية المستخدم وصانع المحتوى بأمان من التسجيل حتى إغلاق الحساب.
- **الخطوات:** تعريف دورة الحساب؛ اختيار المصادقة والجلسات واستعادة الحساب؛ وضع التحقق من البريد/الهاتف عند الحاجة؛ تحديد التحقق من صنّاع المحتوى ومراجعة الحالات؛ تطبيق أقل صلاحية؛ معالجة محاولات الإساءة وتحديد المعدل؛ توثيق الموافقة والاحتفاظ والحذف.
- **المخرجات:** تدفقات حساب موثقة، نموذج صلاحيات، سياسة جلسات واستعادة، واختبارات مصادقة وتفويض.
- **بوابة القبول:** اختبار الحالات الطبيعية والفاشلة ومحاولات الوصول غير المصرح؛ عدم تخزين أسرار في المستودع؛ مراجعة الخصوصية والحسابات المعرّضة للخطر.

### A6 — منتج الفيديو الأساسي
- **الهدف:** مسار موثوق من رفع الفيديو إلى معالجته وتشغيله مع بيانات اللغة والترجمة.
- **الخطوات:** تحديد أنواع الملفات والحدود؛ تصميم الرفع الآمن والتحقق؛ تعريف حالات المعالجة؛ حفظ بيانات الوسائط والملكية؛ بناء مسار التشغيل؛ دعم بيانات الترجمة والتعليقات النصية؛ التعامل مع الانقطاع والفشل وإعادة المحاولة؛ حماية الملفات الخاصة ومنع الوصول المباشر غير المصرح.
- **المخرجات:** مسار رفع ومعالجة وتشغيل، حالات واضحة للمستخدم، عقود تخزين ومعالجة، واختبارات ملفات وأخطاء.
- **بوابة القبول:** اختبار أحجام وصيغ وحالات فشل مختلفة، وصلاحيات الوصول، وسلامة البيانات والأداء؛ لا نشر عام قبل اجتياز مراجعة السلامة A7.

### A7 — الإشراف والسلامة
- **الهدف:** منع إساءة الاستخدام ومعالجة المحتوى المخالف بطريقة قابلة للتفسير والمراجعة.
- **الخطوات:** تعريف السياسات ونطاق المراجعة؛ تحديد ما قبل النشر وما بعده؛ بناء الإبلاغ والتصعيد؛ توثيق أسباب القرار؛ إنشاء مسار استئناف؛ ضبط صلاحيات المشرفين؛ وضع حماية ملائمة للعمر والخصوصية؛ تسجيل تدقيق دون جمع بيانات زائدة.
- **المخرجات:** إجراءات إشراف، حالات وقرارات موثقة، مسارات إبلاغ واستئناف، وصلاحيات وسجل تدقيق.
- **بوابة القبول:** اختبار الإبلاغ والقرار والاستئناف والصلاحيات؛ التحقق من عدم نشر المحتوى المحظور عبر مسارات جانبية؛ مراجعة الخصوصية والإنصاف وإمكانية التراجع عن القرار.

### A8 — البحث والاكتشاف والمجتمع
- **الهدف:** مساعدة المستخدم على اكتشاف المحتوى والمبدعين دون التضحية بالسلامة أو الخصوصية.
- **الخطوات:** بناء البحث والتصنيفات؛ صفحات المبدعين؛ المتابعة والحفظ والتفاعلات المعتمدة؛ تحديد معايير ترتيب النتائج؛ منع التلاعب والرسائل المزعجة؛ مراجعة استخدام البيانات والتخصيص؛ توفير حالات فارغة وأخطاء مفهومة.
- **المخرجات:** بحث وتصنيفات وصفحات مبدعين وتفاعلات ضمن النطاق المعتمد، مع اختبارات الجودة والسلامة.
- **بوابة القبول:** صلة النتائج وسرعتها وإمكانية الوصول إليها، وضبط الصلاحيات ومقاومة الإساءة. أي توصية شخصية تُضاف فقط بعد مراجعة الخصوصية والسلامة وقياسها.

### A9 — الإدارة والدعم والتشغيل
- **الهدف:** تشغيل المنصة ومساعدة المستخدمين دون منح صلاحيات أوسع من الحاجة.
- **الخطوات:** تعريف الأدوار الإدارية؛ ضبط الموافقات؛ بناء أدوات الدعم اللازمة؛ وضع إجراءات الحوادث والتصعيد؛ تسجيل العمليات الحساسة؛ إعداد أدلة التشغيل والاستجابة؛ فصل المهام وتقليل الوصول للبيانات.
- **المخرجات:** صلاحيات إدارية موثقة، أدوات دعم محدودة، سجل تدقيق، وخطط تشغيل وحوادث.
- **بوابة القبول:** اختبار كل دور على المسموح والممنوع، ومراجعة العمليات الحساسة وإمكانية تتبعها، والتحقق من إجراءات الحوادث عمليًا.

### A10 — البيانات والتكاملات
- **الهدف:** حماية بيانات المنصة وضمان نقلها وصيانتها دون ارتباط غير ضروري بمزوّد واحد.
- **الخطوات:** تثبيت مخطط البيانات؛ وضع سياسة ترحيل متوافقة؛ تحديد الاحتفاظ والتصدير والحذف؛ اختبار النسخ الاحتياطي والاستعادة؛ توثيق عقود التكاملات؛ عزل تفاصيل المزوّدين في حدود واضحة؛ قياس الكلفة والحدود؛ فحص التكرار وفقد البيانات.
- **المخرجات:** مخطط وترحيلات موثقة، عقود تكامل، سياسة دورة حياة البيانات، وخطة تصدير واستعادة واستبدال.
- **بوابة القبول:** اختبار الترحيل والاستعادة والتصدير والحذف، ومطابقة البيانات قبل/بعد النقل؛ لا تفعيل مدفوع أو تغيير مزوّد دون الموافقة المطلوبة.

### A11 — الأمان والخصوصية والجودة الشاملة
- **الهدف:** اختبار المنصة ككل، بما فيها الحالات التي تتجاوز المسار الطبيعي.
- **الخطوات:** إعادة مراجعة نموذج التهديد؛ فحص الأسرار والاعتماديات؛ اختبار التفويض وحدود الوصول؛ مراجعة رؤوس الأمان وسياسات المتصفح؛ اختبار الوصولية وRTL؛ قياس الأداء؛ اختبارات الانحدار والتكامل؛ اختبار النسخ الاحتياطي والاسترداد؛ تصنيف المخاطر المتبقية.
- **المخرجات:** تقرير أمان وجودة، نتائج أداء ووصولية، قائمة عيوب مرتبة، وخطة معالجة ومخاطر متبقية.
- **بوابة القبول:** اجتياز الاختبارات المطلوبة وعدم بقاء ثغرات أو أعطال حرجة غير معالجة؛ توثيق نطاق الاختبار والـ commit والقيود. لا يعني النجاح ضمان أمان مطلق.

### A12 — الإصدار والنشر والصيانة
- **الهدف:** إطلاق مضبوط يمكن مراقبته والتراجع عنه وصيانته بعد الإصدار.
- **الخطوات:** إعداد بيئة ما قبل الإنتاج؛ مراجعة قائمة الإصدار؛ التحقق من النسخ الاحتياطي والإعدادات والأسرار؛ إجراء اختبار قبول نهائي؛ نشر تدريجي عند الإمكان؛ مراقبة الأخطاء والأداء؛ اختبار التراجع؛ توثيق الإصدار؛ مراجعة ما بعد الإطلاق وجدولة الصيانة.
- **المخرجات:** سجل إصدار، أدلة قبول ونشر، مؤشرات مراقبة، خطة تراجع، ومسؤوليات صيانة واضحة.
- **بوابة القبول:** لا إصدار إنتاجي قبل موافقة بوابات الأمان والخصوصية والجودة والتشغيل؛ إثبات المراقبة والتراجع والاستعادة، وتوثيق أي مخاطر مقبولة بقرار صريح.

### قاعدة الانتقال بين المراحل
لكل مرحلة: **جرد → نطاق ومعايير قبول → تنفيذ محدود → اختبارات → مراجعة أمن/خصوصية/وصولية/أداء بحسب الصلة → أدلة → قرار الحالة → نقطة توقف وخطوة تالية**. سجّل لكل عنصر B/C معرّفه وأباه ومسار الملف الفعلي وحالته ودليله؛ العناصر المخططة تبقى PLANNED ولا تُعرض كأنها منفّذة. لا تُغلق مرحلة ولا تُحوّلها إلى GREEN بسبب اكتمال الكتابة وحده.

## معيار الجودة المستمر

في **كل مرحلة**: افحص الموجود أولًا، وحدد النطاق والاستثناءات، ثم نفّذ أصغر تغيير مناسب، واختبره، وراجع الأمان والخصوصية والوصولية والأداء وتجربة الهاتف والكمبيوتر بحسب الحاجة، ووثّق الأدلة والمخاطر وما بقي مفتوحًا. عالج الانحدارات بعد كل تغيير، ولا تعتبر العمل منتهيًا لمجرد وجود كود أو نجاح فحص واحد.

- **التصميم:** واضح وأنيق ومتسق، بلا ازدحام أو عناصر شكلية مضللة.
- **الأداء:** تحميل سريع وتفاعل سلس وقياس فعلي قبل ادعاء السرعة.
- **الوصولية واللغات:** لوحة مفاتيح وقارئ شاشة وتباين مناسب، مع دعم العربية RTL واللغات المطلوبة.
